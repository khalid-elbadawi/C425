    Pthread Library Tutorial: Thread Creation and Synchronization

    Introduction

    Welcome to this comprehensive tutorial on the Pthread (POSIX Threads) library in C++. In this lab, you'll learn the fundamentals of thread creation and understand why thread synchronization is crucial in multithreaded programming. By the end of this tutorial, you'll be able to create threads, pass data between them, and understand the challenges that arise when threads work together.

    Prerequisites

    • Basic knowledge of C++ programming
    • Understanding of functions and pointers
    • Familiarity with compilation using g++

    Compilation Instructions

    Throughout this tutorial, compile your programs using: 

    g++ -pthread -o program_name source_file.cpp

    The -pthread flag links the pthread library to your program.

    Part 1: Thread Creation

    1.1 Basic Thread Creation

    Let's start with the most fundamental concept: creating and managing threads.

    Key Functions: - pthread_create(): Creates a new thread - pthread_join(): Waits for a thread to complete - pthread_exit(): Terminates the current thread

    Basic Syntax: 

    int pthread_create(pthread_t *thread, const pthread_attr_t *attr,
                   void *(*start_routine)(void *), void *arg);
int pthread_join(pthread_t thread, void **retval);

    Let's create our first threaded program:

    Example 1.1: Basic Thread Creation

    #include <iostream>
#include <pthread.h>
#include <unistd.h>

// Thread function - this is what the thread will execute
void* threadFunction(void* arg) {
    std::cout << "Hello from thread! Thread ID: " << pthread_self() << std::endl;

    // Simulate some work
    sleep(2);

    std::cout << "Thread finishing execution" << std::endl;
    return nullptr;
}

int main() {
    pthread_t thread;

    std::cout << "Main thread starting. Main thread ID: " << pthread_self() << std::endl;

    // Create the thread
    int result = pthread_create(&thread, nullptr, threadFunction, nullptr);

    if (result != 0) {
        std::cerr << "Error creating thread!" << std::endl;
        return 1;
    }

    std::cout << "Thread created successfully" << std::endl;

    // Wait for the thread to complete
    pthread_join(thread, nullptr);

    std::cout << "Main thread ending" << std::endl;
    return 0;
}

    What's happening here?

    1. We define a thread function threadFunction() that takes a void* parameter and returns void*
    2. In main(), we declare a pthread_t variable to hold the thread identifier
    3. pthread_create() creates the thread with default attributes (nullptr)
    4. pthread_join() makes the main thread wait for the worker thread to finish
    5. Both threads have unique IDs that we can print using pthread_self()

    Expected Output: 

    Main thread starting. Main thread ID: [some number]
Thread created successfully
Hello from thread! Thread ID: [different number]
Thread finishing execution
Main thread ending

    1.2 Thread with Parameters

    Now let's learn how to pass data to threads. Since pthread_create() accepts only a void* parameter, we need to use structures to pass multiple values.

    Example 1.2: Passing Data to Threads

    #include <iostream>
#include <pthread.h>
#include <string>

// Structure to hold thread parameters
struct ThreadData {
    int id;
    std::string message;
    int count;
};

// Thread function that uses the passed data
void* threadFunction(void* arg) {
    // Cast the void* back to our structure
    ThreadData* data = static_cast<ThreadData*>(arg);

    std::cout << "Thread " << data->id << " started" << std::endl;

    // Use the data passed to the thread
    for (int i = 0; i < data->count; i++) {
        std::cout << "Thread " << data->id << ": " << data->message 
                  << " (iteration " << (i + 1) << ")" << std::endl;
    }

    std::cout << "Thread " << data->id << " finished" << std::endl;
    return nullptr;
}

int main() {
    const int NUM_THREADS = 3;
    pthread_t threads[NUM_THREADS];
    ThreadData threadData[NUM_THREADS];

    std::cout << "Creating " << NUM_THREADS << " threads..." << std::endl;

    // Create multiple threads with different data
    for (int i = 0; i < NUM_THREADS; i++) {
        threadData[i].id = i + 1;
        threadData[i].message = "Hello from thread " + std::to_string(i + 1);
        threadData[i].count = (i + 1) * 2;  // Different work load for each thread

        int result = pthread_create(&threads[i], nullptr, threadFunction, &threadData[i]);

        if (result != 0) {
            std::cerr << "Error creating thread " << i << std::endl;
            return 1;
        }
    }

    // Wait for all threads to complete
    for (int i = 0; i < NUM_THREADS; i++) {
        pthread_join(threads[i], nullptr);
    }

    std::cout << "All threads completed!" << std::endl;
    return 0;
}

    Key Points: - We use a struct to package multiple parameters - Each thread gets its own copy of the data structure - We cast void* back to our structure type inside the thread function - Multiple threads can run concurrently, so output order may vary

    Part 2: The Power of Parallelism

    2.1 Understanding the isPrime() Algorithm

    Before we dive into parallel programming, let's understand our example algorithm. We'll use prime number checking because it's computationally intensive and naturally parallelizable.

    Prime Number Checking Algorithm:

    bool isPrime(int n) {
    if (n < 2) return false;
    if (n == 2) return true;
    if (n % 2 == 0) return false;

    // Check odd divisors up to sqrt(n)
    for (int i = 3; i * i <= n; i += 2) {
        if (n % i == 0) {
            return false;
        }
    }
    return true;
}

    Why is this good for parallelism? 1. Independent computations: Checking if number X is prime doesn't depend on checking number Y 2. CPU-intensive: Lots of mathematical operations that can benefit from parallel processing 3. Scalable workload: We can easily divide the range of numbers among multiple threads

    2.2 Simple Sequential Example

    Let's establish our baseline with a sequential (single-threaded) implementation:

    Example 2.2: Sequential Prime Counting

    #include <iostream>
#include <chrono>

bool isPrime(int n) {
    if (n < 2) return false;
    if (n == 2) return true;
    if (n % 2 == 0) return false;

    for (int i = 3; i * i <= n; i += 2) {
        if (n % i == 0) {
            return false;
        }
    }
    return true;
}

int countPrimesSequential(int start, int end) {
    int count = 0;
    for (int i = start; i <= end; i++) {
        if (isPrime(i)) {
            count++;
        }
    }
    return count;
}

int main() {
    const int START = 1;
    const int END = 100000;

    std::cout << "Counting primes from " << START << " to " << END << " (sequential)" << std::endl;

    // Measure execution time
    auto start_time = std::chrono::high_resolution_clock::now();

    int primeCount = countPrimesSequential(START, END);

    auto end_time = std::chrono::high_resolution_clock::now();
    auto duration = std::chrono::duration_cast<std::chrono::milliseconds>(end_time - start_time);

    std::cout << "Found " << primeCount << " prime numbers" << std::endl;
    std::cout << "Sequential execution time: " << duration.count() << " milliseconds" << std::endl;

    return 0;
}

    Run this program and note the execution time. This will be our baseline for comparison.

    2.3 Parallelism Example

    Now let's harness the power of multiple threads to speed up our computation!

    2.3.1 countPrimesSequential() Analysis

    Our sequential function processes numbers one by one in a single thread: - Input: Range of numbers (start to end) - Process: Check each number individually - Output: Count of prime numbers - Limitation: Uses only one CPU core

    2.3.2 countPrimesParallel() Components

    To parallelize this, we need three key components:

    Component 1: Thread Data Structure 

    struct ThreadData {
    int start;        // Starting number for this thread
    int end;          // Ending number for this thread
    int result;       // Store the count of primes found
    int threadId;     // For identification and debugging
};

    Component 2: Thread Function 

    void* countPrimesThread(void* arg) {
    ThreadData* data = static_cast<ThreadData*>(arg);

    std::cout << "Thread " << data->threadId 
              << " processing range [" << data->start 
              << ", " << data->end << "]" << std::endl;

    data->result = 0;
    for (int i = data->start; i <= data->end; i++) {
        if (isPrime(i)) {
            data->result++;
        }
    }

    std::cout << "Thread " << data->threadId 
              << " found " << data->result << " primes" << std::endl;

    return nullptr;
}

    Component 3: Work Distribution Strategy 

    // Divide the work evenly among threads
int rangeSize = (END - START + 1) / NUM_THREADS;
for (int i = 0; i < NUM_THREADS; i++) {
    threadData[i].start = START + i * rangeSize;
    threadData[i].end = (i == NUM_THREADS - 1) ? END : threadData[i].start + rangeSize - 1;
    threadData[i].threadId = i;
}

    2.3.3 Complete Parallel Program

    Example 2.3: Parallel Prime Counting

    #include <iostream>
#include <pthread.h>
#include <chrono>

struct ThreadData {
    int start;
    int end;
    int result;
    int threadId;
};

bool isPrime(int n) {
    if (n < 2) return false;
    if (n == 2) return true;
    if (n % 2 == 0) return false;

    for (int i = 3; i * i <= n; i += 2) {
        if (n % i == 0) {
            return false;
        }
    }
    return true;
}

void* countPrimesThread(void* arg) {
    ThreadData* data = static_cast<ThreadData*>(arg);

    std::cout << "Thread " << data->threadId 
              << " processing range [" << data->start 
              << ", " << data->end << "]" << std::endl;

    data->result = 0;
    for (int i = data->start; i <= data->end; i++) {
        if (isPrime(i)) {
            data->result++;
        }
    }

    std::cout << "Thread " << data->threadId 
              << " found " << data->result << " primes" << std::endl;

    return nullptr;
}

int countPrimesParallel(int start, int end, int numThreads) {
    pthread_t* threads = new pthread_t[numThreads];
    ThreadData* threadData = new ThreadData[numThreads];

    // Distribute work among threads
    int rangeSize = (end - start + 1) / numThreads;

    std::cout << "Creating " << numThreads << " threads for parallel processing..." << std::endl;

    // Create threads
    for (int i = 0; i < numThreads; i++) {
        threadData[i].start = start + i * rangeSize;
        threadData[i].end = (i == numThreads - 1) ? end : threadData[i].start + rangeSize - 1;
        threadData[i].threadId = i;
        threadData[i].result = 0;

        int result = pthread_create(&threads[i], nullptr, countPrimesThread, &threadData[i]);
        if (result != 0) {
            std::cerr << "Error creating thread " << i << std::endl;
            return -1;
        }
    }

    // Wait for all threads to complete
    for (int i = 0; i < numThreads; i++) {
        pthread_join(threads[i], nullptr);
    }

    // Combine results from all threads
    int totalPrimes = 0;
    for (int i = 0; i < numThreads; i++) {
        totalPrimes += threadData[i].result;
    }

    delete[] threads;
    delete[] threadData;

    return totalPrimes;
}

// Sequential version for comparison
int countPrimesSequential(int start, int end) {
    int count = 0;
    for (int i = start; i <= end; i++) {
        if (isPrime(i)) {
            count++;
        }
    }
    return count;
}

int main() {
    const int START = 1;
    const int END = 100000;
    const int NUM_THREADS = 4;

    std::cout << "=== Prime Number Counting Performance Comparison ===" << std::endl;
    std::cout << "Range: " << START << " to " << END << std::endl << std::endl;

    // Sequential execution
    std::cout << "1. Sequential Execution:" << std::endl;
    auto start_time = std::chrono::high_resolution_clock::now();
    int sequentialResult = countPrimesSequential(START, END);
    auto end_time = std::chrono::high_resolution_clock::now();
    auto sequentialDuration = std::chrono::duration_cast<std::chrono::milliseconds>(end_time - start_time);

    std::cout << "Found " << sequentialResult << " prime numbers" << std::endl;
    std::cout << "Sequential time: " << sequentialDuration.count() << " ms" << std::endl << std::endl;

    // Parallel execution
    std::cout << "2. Parallel Execution (" << NUM_THREADS << " threads):" << std::endl;
    start_time = std::chrono::high_resolution_clock::now();
    int parallelResult = countPrimesParallel(START, END, NUM_THREADS);
    end_time = std::chrono::high_resolution_clock::now();
    auto parallelDuration = std::chrono::duration_cast<std::chrono::milliseconds>(end_time - start_time);

    std::cout << "Found " << parallelResult << " prime numbers" << std::endl;
    std::cout << "Parallel time: " << parallelDuration.count() << " ms" << std::endl << std::endl;

    // Performance analysis
    std::cout << "=== Performance Analysis ===" << std::endl;
    std::cout << "Correctness check: " << (sequentialResult == parallelResult ? "PASSED" : "FAILED") << std::endl;

    if (parallelDuration.count() > 0) {
        double speedup = static_cast<double>(sequentialDuration.count()) / parallelDuration.count();
        std::cout << "Speedup: " << speedup << "x" << std::endl;
        std::cout << "Efficiency: " << (speedup / NUM_THREADS) * 100 << "%" << std::endl;
    }

    return 0;
}

    Expected Output Analysis:

    When you run this program, you should see: 1. Correctness: Both methods should find the same number of primes 2. Performance: The parallel version should be faster (speedup depends on your CPU) 3. Thread Activity: You'll see each thread reporting its assigned range and results

    Try experimenting with different values: - Change NUM_THREADS (try 2, 4, 8) - Change the range (try 1 to 50000 or 1 to 200000) - Observe how performance changes

    Part 3: Understanding Thread Synchronization

    Conceptual Foundation

    So far, our threads have worked independently—each thread processed its own range of numbers without interacting with others. This worked well because: - Each thread had its own data - No thread needed to access shared resources - Results were combined only after all threads finished

    However, in many real-world scenarios, threads need to: - Share data structures (arrays, lists, counters) - Access shared resources (files, network connections) - Coordinate their activities

    Critical Section Concept

    A critical section is a code segment where threads access shared resources. Problems arise when multiple threads enter the critical section simultaneously.

    Example of a Critical Section: 

    // Shared variable
int globalCounter = 0;

// Critical section - accessing shared variable
void incrementCounter() {
    globalCounter++;  // This is NOT atomic!
}

    The increment operation globalCounter++ actually involves three steps: 1. Read the current value of globalCounter 2. Add 1 to that value 3. Write the new value back to globalCounter

    If two threads execute these steps simultaneously, we can lose updates!

    Overview of Synchronization Mechanisms

    Mutex (Mutual Exclusion): - Ensures only one thread can access a critical section at a time - Like a lock on a bathroom door

    Semaphore: - Controls access to a resource with limited capacity - Like a parking lot with limited spaces

    Condition Variables: - Allow threads to wait for certain conditions - Like waiting for a signal to proceed

    In this tutorial, we'll focus on mutex as it's the most fundamental synchronization mechanism.

    Part 4: The Problem - Race Conditions

    Let's demonstrate why synchronization is necessary by creating a program that exhibits race conditions.

    Race Condition Demonstration

    Example 4.1: The Broken Counter

    #include <iostream>
#include <pthread.h>

// Shared global variable - THIS IS THE PROBLEM!
int globalCounter = 0;
const int INCREMENTS_PER_THREAD = 100000;

struct ThreadData {
    int threadId;
};

void* incrementCounter(void* arg) {
    ThreadData* data = static_cast<ThreadData*>(arg);

    std::cout << "Thread " << data->threadId << " starting to increment..." << std::endl;

    // Each thread increments the counter many times
    for (int i = 0; i < INCREMENTS_PER_THREAD; i++) {
        globalCounter++;  // RACE CONDITION: Multiple threads accessing globalCounter
    }

    std::cout << "Thread " << data->threadId << " finished incrementing" << std::endl;
    return nullptr;
}

int main() {
    const int NUM_THREADS = 4;
    pthread_t threads[NUM_THREADS];
    ThreadData threadData[NUM_THREADS];

    std::cout << "=== Race Condition Demonstration ===" << std::endl;
    std::cout << "Expected final value: " << (NUM_THREADS * INCREMENTS_PER_THREAD) << std::endl;
    std::cout << "Initial counter value: " << globalCounter << std::endl << std::endl;

    // Create threads
    for (int i = 0; i < NUM_THREADS; i++) {
        threadData[i].threadId = i;
        pthread_create(&threads[i], nullptr, incrementCounter, &threadData[i]);
    }

    // Wait for all threads to complete
    for (int i = 0; i < NUM_THREADS; i++) {
        pthread_join(threads[i], nullptr);
    }

    std::cout << std::endl << "=== Results ===" << std::endl;
    std::cout << "Final counter value: " << globalCounter << std::endl;
    std::cout << "Expected value: " << (NUM_THREADS * INCREMENTS_PER_THREAD) << std::endl;

    if (globalCounter == (NUM_THREADS * INCREMENTS_PER_THREAD)) {
        std::cout << "Result: CORRECT (lucky!)" << std::endl;
    } else {
        std::cout << "Result: INCORRECT - Race condition occurred!" << std::endl;
        std::cout << "Lost updates: " << (NUM_THREADS * INCREMENTS_PER_THREAD) - globalCounter << std::endl;
    }

    return 0;
}

    Analysis: What Goes Wrong and Why

    Run this program multiple times. You'll likely see different results each time, and the final counter value will often be less than expected.

    Why does this happen?

    1. The increment operation globalCounter++ is not atomic: 

      Thread A: Read globalCounter (value = 100)
Thread B: Read globalCounter (value = 100)  ← Same value!
Thread A: Calculate 100 + 1 = 101
Thread B: Calculate 100 + 1 = 101          ← Same calculation!
Thread A: Write 101 to globalCounter
Thread B: Write 101 to globalCounter       ← Overwrites A's work!

    2. Lost updates: When two threads read the same value and both increment it, one increment is lost.

    3. Non-deterministic behavior: The timing of thread execution is unpredictable, leading to different results each run.

    Try running the program with different parameters: - Reduce INCREMENTS_PER_THREAD to 1000 - does the problem still occur? - Increase NUM_THREADS to 8 - does the problem get worse? - Add sleep() calls in the loop - how does this affect the race condition?

    Understanding the Race Window

    The "race window" is the time between reading a shared variable and writing back to it. The longer this window, the more likely race conditions become.

    // Wider race window
int temp = globalCounter;  // Step 1: Read
temp = temp + 1;          // Step 2: Modify  
globalCounter = temp;     // Step 3: Write
// More time for another thread to interfere!

// Narrower race window
globalCounter++;          // All three steps together
// Still not atomic, but smaller window

    Summary: Why We Need Synchronization

    This demonstration shows that even simple operations like incrementing a counter can go wrong in multithreaded environments. We need synchronization mechanisms to:

    1. Ensure atomicity: Operations on shared data complete without interference
    2. Prevent race conditions: Control access to critical sections
    3. Maintain data consistency: Ensure shared data remains in a valid state
    4. Provide predictable behavior: Make multithreaded programs deterministic
