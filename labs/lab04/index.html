    What is the expected sum?

    The numbers in the file are generated using RAND()*100 in Excel program and repeated one million times. Click here to download the file [5MB].

    We can estimate the sum of those values as follows. Let's consider n independent standard uniform random variables, denoted as \(X_1, X_2, \ldots, X_n\), each uniformly distributed on the interval \([0, 100]\). We want to estimate the expected value of their sum, which can be expressed as:

    \[ E(X_1 + X_2 + \ldots + X_n) \]

    The key property we'll use here is the linearity of expectation. It states that for any random variables \(Y_1, Y_2, \ldots, Y_n\), if their expectations exist, then:

    \[ E(Y_1 + Y_2 + \ldots + Y_n) = E(Y_1) + E(Y_2) + \ldots + E(Y_n) \]

    Applying this to our case, where \(Y_i = X_i\), we have:

    \[ E(X_1 + X_2 + \ldots + X_n) = E(X_1) + E(X_2) + \ldots + E(X_n) \]

    Since each \(X_i\) is uniformly distributed on \([0, 100]\), their expected value is:

    \[ E(X_i) = \frac{100-0}{2}=50 \]

    Therefore:

    \[ E(X_1 + X_2 + \ldots + X_n) = n \cdot 50 = 50n \]

    So, \(\sum_{i=1}^n x_i \approx 50n\). Hence, you can test the program several times with different values of N. In each run, you can estimate the expected sum.

    The Parallel Program

    We are going to embarrasingly parallelize the serial program by dividing the work among NP threads/processes. In particular, we are going to parallelize the following code:

    41
42
43
        double sum = 0;
    for (int i=0; i<N; i++) 
        sum = sum + x[i];

    The data items in the array x will be distributed among the NP threads, as we did in Lab(2). All threads are going to execute a single task, named computeSum(), to emulate SPMD. Then, we manually assign an ID number for each thread, as depicted in the following diagram:

    The computeSum() is implemented as follows:

    void *computeSum (void *tid)
{
    int id = (int)(uintptr_t)tid;
    int block_length = N / NP;
    int start = id * block_length;
    int end = start + block_length;

    for (int i=start; i<end; i++) {
        sum = sum + x[i];
    }

    return nullptr;
}

    void * data type

    You may notice that the function computeSum() has the following prototype: 

        void *computeSum (void *);
    This is the default prototype of the thread function as mentioned in POSIX standard. It means the thread function takes an object (any object) and returns an object (any object).

    Since, we are passing an integer value, we must convert it from int to void * using type casting operator(s). Then, inside the thread function, we reverse the type casting (i.e., from void * to int).

    Thread Synchronization

    The program in Exercise (1) has a serious BUG. All threads are accessing and modifying the shared variable sum. This problem is known as race condition, because the threads or processes are in a "race" to carry out the highlighted operation:

    68
69
    for (int i=start; i<end; i++)
    sum = sum + x[i];

    Therefore, Line 69 is a critical section. Now, it's our job as programmers to ensure mutually exclusive access to the critical section by using mutex (or simply lock). To add a mutex:

    1. Declare a mutex variable (globally) as follows: 

      pthread_mutex_t mtx;

    2. Initialize the mutex (should be initialized before forking any thread): 

      pthread_mutex_init(&mtx, nullptr);

    3. Finally, protect the critical section by using the mutex: 

      for (int i=start; i<end; i++) {
    pthread_mutex_lock(&mtx);
    sum = sum + x[i];
    pthread_mutex_unlock(&mtx);
}

    Exercise (3)

    Suppose we toss darts randomly at a square dartboard, whose bullseye is at the origin, and whose sides are two feet in length. Suppose also that there’s a circle inscribed in the square dartboard. The radius of the circle is 1 foot, and its area is \(\pi\) square feet. If the points that are hit by the darts are uniformly distributed (and we always hit the square), then the number of darts that hit inside the circle should approximately satisfy the equation:

    \[ \frac{\text{number in circle}}{\text{total number of tosses}} = \frac{\pi}{4}, \]

    since the ratio of the area of the circle to the area of the square is \(\pi/4\).

    We can use this formula to estimate the value of \(\pi\) with a random number generator:

    number_in_circle = 0;
for ( toss = 0; toss < number_of_tosses; toss++) {
    x = random double between −1 and 1;
    y = random double between −1 and 1;
    distance_squared = x∗x + y∗y;
    if ( distance_squared <= 1)
        number_in_circle ++;
}
pi_estimate = 4 ∗ number_in_circle / (( double) number_of_tosses);

    This is called a Monte Carlo method, since it uses randomness (the dart tosses).

    Write a Pthreads program that uses a Monte Carlo method to estimate \(\pi\). The main thread should read in the total number of tosses and print the estimate. You may want to use long long ints for the number of hits in the circle and the number of tosses, since both may have to be very large to get a reasonable estimate of \(\pi\).
