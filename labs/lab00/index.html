    Lab(0): Setting Up Your Development Environment

    "A craftsman is only as good as his tools. Before we write a single line of code, we build the workshop."

    Overview

    In this lab you will set up a complete, professional-grade development environment on your own device. By the end, you will have:

    • A C++ compiler (GCC 13.3)
    • A Go compiler (latest stable)
    • Visual Studio Code as your IDE with full debugging support
    • A working Hello World program in both languages — compiled, run, and debugged

    This environment is what you will use throughout the entire course. Take the time to do it right.

    Choose Your Path

    Which path is mine?

    • You have a Windows laptop or PC → follow Path A
    • You only have an Android tablet or phone → follow Path B

    Path A - Windows

    A.1 - Install the C++ Compiler (GCC 13.3 via WinLibs)

    WinLibs provides native Windows builds of GCC without requiring any Linux subsystem or virtual machine.

    Step 1 - Download GCC 13.3

    Go to winlibs.com and download the GCC 13.3 release. Choose:

    • Architecture: x86_64 (64-bit)
    • Thread model: POSIX
    • Runtime library: UCRT or MSVCRT (either works)
    • Format: 7-Zip archive (.7z) or Zip (.zip)

    Version matters

    Make sure you select POSIX specifically. Later labs depend on Pthread Library.

    Step 2 - Extract and place

    Extract the archive. You will get a folder named mingw64. Move it to a clean path with no spaces:

    C:\mingw64

    Avoid paths with spaces

    Paths like C:\Program Files\mingw64 will cause cryptic build failures. Always use C:\mingw64.

    Step 3 - Add to System PATH

    1. Press Win + S and search for "Edit the system environment variables"
    2. Click Environment Variables
    3. Under System variables, find Path → click Edit
    4. Click New and add: 
      C:\mingw64\bin
    5. Click OK on all dialogs

    Step 4 - Verify

    Open a new Command Prompt or PowerShell window - existing ones won't see the updated PATH:

    gcc --version
g++ --version

    Expected output:

    gcc (MinGW-W64 x86_64-ucrt-posix-seh) 13.3.0

    A.2 - Install the Go Compiler

    Step 1 - Download Go

    Go to go.dev/dl and download the Windows AMD64 installer (.msi file).

    Step 2 - Install

    Run the installer. It will install Go to C:\Go and automatically add it to your PATH.

    Step 3 - Verify

    Open a new terminal:

    go version

    Expected output:

    go version go1.x.x windows/amd64

    A.3 - Install Visual Studio Code

    Step 1 - Download

    Go to code.visualstudio.com and download the Windows installer.

    Step 2 - Install

    During installation, check both options:

    • ✅ Add "Open with Code" action to Windows Explorer file context menu
    • ✅ Add to PATH

    Step 3 - Install essential extensions

    Press Ctrl+Shift+X and install:

    Extension Publisher Purpose
    C/C++ Microsoft IntelliSense, debugging
    C/C++ Extension Pack Microsoft Full C++ toolchain integration
    Go Go Team at Google IntelliSense, debugging, formatting

    Step 4 - Configure the C++ compiler path

    Press Ctrl+Shift+P, type "C/C++: Edit Configurations (UI)" and select it. Set:

    • Compiler path: C:\mingw64\bin\g++.exe
    • IntelliSense mode: windows-gcc-x64

    A.4 - Verify: Hello World in C++

    Create a new file hello.cpp:

    hello.cpp
    #include <iostream>

int main() {
    std::cout << "Hello, World! - C++ on Windows" << std::endl;
    return 0;
}

    Open the VS Code terminal (Ctrl+`) and compile:

    g++ hello.cpp -o hello.exe
./hello.exe

    Expected output:

    Hello, World! - C++ on Windows

    A.5 - Verify: Hello World in Go

    Create a new file hello.go:

    hello.go
    package main

import "fmt"

func main() {
    fmt.Println("Hello, World! - Go on Windows")
}

    Run it:

    go run hello.go

    Expected output:

    Hello, World! - Go on Windows

    A.6 - Set Up the Debugger (C++)

    VS Code uses launch.json to configure the debugger.

    Step 1 -- Open your project folder (File → Open Folder)

    Step 2 -- Press F5 → select C++ (GDB/LLDB) → g++.exe build and debug active file

    VS Code creates .vscode/launch.json automatically. Confirm it contains:

    .vscode/launch.json
    {
    "miDebuggerPath": "C:\\mingw64\\bin\\gdb.exe"
}

    Step 3 - Set a breakpoint by clicking the left margin next to any line number, then press F5.

    Path A Complete

    You now have a fully functional C++/Go development environment on Windows. Proceed to the verification checklist.

    Path B - Android (Tablet or Phone)

    Prerequisites

    Before you begin, make sure you have:

    Requirement Details
    📶 Internet connection Required throughout the setup — downloads are large
    💾 Free internal storage At least 3 GB free
    ⬇️ Download budget Approximately 650 MB total download
    🔋 Battery Plug in — this setup takes time

    What we are building

    Android does not run native Linux programs. We solve this by layering three components on top of each other:

    graph TD
    A[🤖 Android OS] --> B[📦 Termux\nLinux terminal emulator]
    B --> C[🐧 Ubuntu 24.04\nvia proot-distro]
    C --> D[⚙️ GCC / G++ 13.x\nC++ Compiler]
    C --> E[🔵 Go Compiler]
    C --> F[💻 code-server\nVS Code in browser]
    F --> G[🌐 Browser\nlocalhost:8080]

    B.1 - Install Termux

    Do NOT use the Play Store version

    The Google Play Store version of Termux is outdated and abandoned. It will not work correctly. You must install version v0.118.3 directly from GitHub.

    Step 1 - Download the APK

    Open your browser and go to the Termux releases page on GitHub:

    https://github.com/termux/termux-app/releases/tag/v0.118.3

    Download the file:

    termux-app_v0.118.3+github-debug_arm64-v8a.apk

    Which APK to choose?

    • Most modern Android phones and tablets use arm64-v8a
    • If installation fails, try the universal variant instead

    Step 2 - Allow installation from unknown sources

    Android will ask permission to install apps from your browser. Tap Settings → Allow when prompted.

    Step 3 - Install and open Termux

    Tap the downloaded APK to install, then open Termux.

    Step 4 - Initial update

    pkg update && pkg upgrade -y

    Press Enter to accept all prompts.

    B.2 - Install proot-distro

    proot-distro is a package manager for Linux distributions inside Termux. It runs Ubuntu without requiring root access on your device.

    pkg install proot-distro -y

    This downloads approximately 100–200 MiB and takes 635MB internal storage.

    B.3 - Install Ubuntu 24.04

    VPN may be required

    proot-distro downloads Ubuntu from Docker Hub. In some regions, Docker Hub blocks anonymous downloads. If you see an "Unauthorized" error, connect to a VPN and retry. You will only need the VPN during package installation steps -- not for day-to-day use.

    proot-distro install ubuntu:24.04

    Don't worry. This downloads only 27MB, a highly compressed, minimal root filesystem., but it will expand to 200-300MB.

    Wait for the success message:

    [*] Installing 'ubuntu:24.04' as 'ubuntu'...
[*] Downloading...
[*] Extracting...
[*] Done.

    Log into Ubuntu:

    proot-distro login ubuntu

    Your shell prompt changes -- this confirms you are now inside Ubuntu:

    # Termux prompt (before)
~ $

# Ubuntu prompt (after)
root@localhost:~#

    B.4 - Install C++, Go, and code-server

    We install everything in one session. Inside Ubuntu, run each block in order.

    Update the package index:

    apt update && apt upgrade -y

    Install C++ compiler and build tools:

    apt install -y build-essential gcc g++

    Note

    build-essential installs GCC, G++, Make, and all related tools in a single command.

    Install Go:

    apt install -y golang-go

    Verify both compilers before continuing:

    gcc --version
g++ --version
go version

    Expected output:

    gcc (Ubuntu 13.x.x) 13.x.x
g++ (Ubuntu 13.x.x) 13.x.x
go version go1.x.x linux/arm64

    Install code-server:

    curl -fsSL https://code-server.dev/install.sh | sh

    This step takes several minutes. When it finishes, configure your password immediately:

    mkdir -p ~/.config/code-server
cat > ~/.config/code-server/config.yaml << EOF
bind-addr: 127.0.0.1:8080
auth: password
password: changeme123
cert: false
EOF

    Set your password now

    Replace changeme123 with a password of your choice before proceeding. Without this configuration, code-server will generate a random password on each launch.

    B.5 - Start code-server and Open VS Code

    Start the server:

    code-server

    You will see:

    [info] HTTP server listening on http://127.0.0.1:8080/

    Open your browser in split-screen mode (see note below) and navigate to:

    http://127.0.0.1:8080

    Enter your password. VS Code opens in your browser.

    Use split-screen — this is important

    Android suspends background apps to save battery. If you open the browser fullscreen, Android will freeze the Termux process and code-server will stop responding.

    Always run Termux and your browser side by side in split-screen mode.

    To enable split-screen on most Android devices: long-press the recent apps button, or drag the app to the top of the screen when in the recent apps view.

    graph LR
    A["🔴 Browser fullscreen\nTermux suspended\ncode-server frozen ❌"] 
    B["✅ Split-screen\nTermux visible\ncode-server active ✔️"]
    A -. "Switch to" .-> B

    style A fill:#ff5252,color:#fff
    style B fill:#4caf50,color:#fff

    Additional protection against Android killing Termux:

    Back in the Termux panel, run:

    termux-wake-lock

    Then go to Android Settings → Apps → Termux → Battery → Unrestricted.

    B.6 - Install VS Code Extensions

    Inside code-server, press Ctrl+Shift+X and install:

    Extension Publisher Purpose
    C/C++ Microsoft IntelliSense, debugging
    C/C++ Extension Pack Microsoft Full C++ toolchain integration
    Go Go Team at Google Go support, debugging

    B.7 - Verify: Hello World in C++

    Open the integrated terminal in code-server (Ctrl+`) and run:

    mkdir -p ~/projects && cd ~/projects
cat > hello.cpp << 'EOF'
#include <iostream>

int main() {
    std::cout << "Hello, World! - C++ on Android" << std::endl;
    return 0;
}
EOF
g++ hello.cpp -o hello
./hello

    Expected output:

    Hello, World! - C++ on Android

    B.8 — Verify: Hello World in Go

    cat > hello.go << 'EOF'
package main

import "fmt"

func main() {
    fmt.Println("Hello, World! - Go on Android")
}
EOF
go run hello.go

    Expected output:

    Hello, World! - Go on Android

    B.9 - Managing Your Session (Start & Stop)

    The complete session lifecycle is illustrated below:

    sequenceDiagram
    participant You
    participant Termux
    participant Ubuntu
    participant Browser

    You->>Termux: Open Termux app
    You->>Termux: termux-wake-lock
    You->>Termux: proot-distro login ubuntu
    Termux->>Ubuntu: Ubuntu shell starts
    You->>Ubuntu: code-server
    Ubuntu-->>Browser: Listening on :8080
    You->>Browser: Open http://127.0.0.1:8080
    Browser-->>You: VS Code UI ready ✅

    Note over You,Browser: Work on your code...

    You->>Ubuntu: pkill code-server
    You->>Ubuntu: exit
    Ubuntu-->>Termux: Returns to Termux
    You->>Termux: exit
    Termux-->>You: Session ended

    One-command startup script

    Run this once to create a shortcut (exit Ubuntu first):

    cat > ~/start-dev.sh << 'EOF'
#!/data/data/com.termux/files/usr/bin/bash
termux-wake-lock
proot-distro login ubuntu -- bash -c "code-server"
EOF
chmod +x ~/start-dev.sh

    From now on, start your entire environment with a single command:

    bash ~/start-dev.sh

    Then open your browser to http://127.0.0.1:8080.

    Stopping the session:

    # In the Ubuntu terminal inside code-server:
pkill code-server

# Then exit Ubuntu:
exit

# Then exit Termux:
exit

    Path B Complete

    You now have a full Linux development environment on your Android device. Proceed to the verification checklist.

    Final Verification Checklist

    Before submitting this lab, confirm every item below:

    • gcc --version shows GCC 13.x
    • g++ --version shows G++ 13.x
    • go version shows Go 1.x
    • VS Code (or code-server) opens successfully
    • C/C++ extension is installed and active
    • Go extension is installed and active
    • hello.cpp compiles and runs correctly
    • hello.go runs correctly
    • You can set a breakpoint and step through code in the debugger

    Troubleshooting

    gcc: command not found (Windows)

    The compiler is not on your PATH. Make sure you added C:\mingw64\bin to the System PATH (not User PATH) and opened a new terminal window after doing so.

    proot-distro install fails with 'Unauthorized' (Android)

    Docker Hub is blocked in your region. Connect to a VPN and retry. Once Ubuntu is installed, the VPN is only needed when installing new packages with apt — not for normal coding sessions.

    code-server loads very slowly or hangs

    The most common cause is Android suspending Termux in the background. Make sure you are using split-screen mode with Termux visible alongside your browser. Also run termux-wake-lock and disable battery optimization for Termux in Android settings.

    I accidentally deleted Ubuntu with proot-distro remove

    Your source files may be lost if they were stored inside the Ubuntu container. Always back up important work to Termux's home directory (~/) or use the backup command before removing: 

    proot-distro backup ubuntu
    To reinstall Ubuntu from scratch, simply repeat steps B.3 and B.4.

    I closed Termux and lost my code-server session

    Your files are safe — they persist on disk inside the proot-distro container. Only the running processes are lost. Simply run bash ~/start-dev.sh to resume.

    The Go extension asks me to install tools on first launch

    Click Install All when prompted. The extension will download gopls, dlv (debugger), and other tools automatically. This requires an internet connection and may take a few minutes.

    Two error messages appear when code-server starts on Android

    You may see Unable to retrieve mac address and Unsupported platform errors in the terminal. These are harmless warnings — Android does not expose device identifiers the way desktop Linux does. code-server starts and runs correctly despite these messages.
