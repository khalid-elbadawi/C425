    Lab Overview

    This lab provides a hands-on introduction to concurrent programming in C++ using the POSIX Threads (Pthreads) library. You'll learn the fundamental concepts of creating and managing threads to perform tasks in parallel. The tutorial will first guide you through thread creation and data passing. Then, you'll build a program that demonstrates the performance benefits of parallelism by comparing a sequential task to a multithreaded one. Finally, you'll learn about the critical problem of race conditions and how to solve it using mutexes for thread synchronization.

    Lab Objectives

    Upon completing this lab, you will be able to:

    • ✅ Explain the lifecycle of a thread and how it differs from a process.
    • ✅ Write C++ code to create, manage, and join threads using the Pthread library.
    • ✅ Pass single or multiple arguments to a thread function.
    • ✅ Implement a parallel algorithm to speed up a computationally intensive task.
    • ✅ Measure and analyze the performance gains using metrics like speedup and efficiency.
    • ✅ Identify race conditions and protect shared data using mutexes.

    Prerequisites

    • Basic C++ Knowledge: You should be comfortable with C++ syntax, functions, data types, pointers, and structs.
    • Development Environment: A Unix-like environment (Linux, macOS, or Windows Subsystem for Linux) with a C++ compiler (like g++) installed.
    • Command-Line Familiarity: Basic experience with compiling and running C++ programs from the terminal is necessary. To compile a Pthread program, you must link the pthread library using the -pthread flag: g++ your_program.cpp -o your_program -pthread.

    1. Thread Creation

    In this section, you'll learn the basics of creating and managing a new thread of execution within your program.

    What is a Thread?

    A thread is the smallest unit of execution within a process. A single process can have multiple threads running concurrently, all sharing the same memory space (like global variables and the heap). However, each thread has its own private program counter, stack, and set of registers. This shared memory model makes communication between threads efficient but also introduces synchronization challenges.

    The main thread of your program starts when main() is called. This main thread can then create other threads. This process is often referred to as forking.

    Thread Forking and Joining

    • Forking: The pthread_create function creates a new thread. After the call, the original (parent) thread and the new (child) thread run concurrently.

      Diagram: Thread Forking 

      graph TD
    A[Main Thread] --> B{pthread_create()};
    B --> C[Main Thread Continues];
    B --> D[New Thread Executes];

    • Joining: A thread can wait for another thread to complete by calling pthread_join. This is a blocking call, pausing the calling thread until the target thread terminates. This is essential for retrieving results computed by a child thread.

      Diagram: Thread Joining 

      graph TD
    subgraph Parallel Execution
        A[Main Thread]
        B[Child Thread]
    end
    A -- Runs Concurrently --> C{pthread_join(child)};
    B -- Runs Concurrently --> D[Finishes Task];
    D --> C;
    C -- Resumes Execution --> E[Main Thread Continues];

    Creating a Simple Thread

    To get started, you must include the pthread.h header file. Let's create a thread that prints a simple message.

    #include <iostream>
#include <pthread.h>

// The function that the new thread will execute.
void* myFirstThread(void* arg) {
    std::cout << "Hello from the new thread!" << std::endl;
    return nullptr;
}

int main() {
    pthread_t thread_id; // Opaque variable to store the thread identifier

    std::cout << "Main thread: Creating a new thread." << std::endl;

    // Create the new thread
    pthread_create(&thread_id, nullptr, myFirstThread, nullptr);

    // Wait for the created thread to finish its execution
    pthread_join(thread_id, nullptr);

    std::cout << "Main thread: The new thread has finished." << std::endl;

    return 0;
}

    Explanation:

    • #include <pthread.h>: Includes the Pthread library.
    • nullptr vs NULL: We use nullptr, the modern C++ standard for representing a null pointer, instead of the older C-style NULL macro.
    • pthread_create(&thread_id, nullptr, myFirstThread, nullptr): Creates the thread.
      • 1st argument: A pointer to thread_id to store the thread's identifier.
      • 2nd argument: A pointer to thread attributes; nullptr specifies default attributes.
      • 3rd argument: A pointer to the function the thread will execute.
      • 4th argument: A void* pointer to the argument for the thread function.
    • pthread_join(thread_id, nullptr): The main thread waits here until the thread identified by thread_id completes.

    Sample Output:

    Main thread: Creating a new thread.
Hello from the new thread!
Main thread: The new thread has finished.

    Passing Arguments to a Thread

    You can pass a single value to a thread by casting a pointer to void*.

    #include <iostream>
#include <pthread.h>

void* printMessage(void* msg) {
    // Cast the void* argument back to its original type
    char* message = (char*) msg;
    std::cout << message << std::endl;
    return nullptr;
}

int main() {
    pthread_t thread1, thread2;
    const char* message1 = "This is thread 1.";
    const char* message2 = "This is thread 2.";

    // Create threads and pass a string literal to each
    pthread_create(&thread1, nullptr, printMessage, (void*) message1);
    pthread_create(&thread2, nullptr, printMessage, (void*) message2);

    // Wait for the threads to finish
    pthread_join(thread1, nullptr);
    pthread_join(thread2, nullptr);

    return 0;
}

    Sample Output:

    This is thread 1.
This is thread 2.

    Passing Multiple Values

    To pass multiple values, you must bundle them into a struct and pass a pointer to an instance of that struct.

    #include <iostream>
#include <pthread.h>
#include <string>

// A struct to hold multiple arguments for our thread
struct ThreadArgs {
    int id;
    std::string message;
};

void* printArgs(void* arg) {
    // Cast the void* back to our struct type
    ThreadArgs* args = (ThreadArgs*) arg;

    std::cout << "Thread ID: " << args->id
              << ", Message: '" << args->message << "'" << std::endl;

    // Free the dynamically allocated memory to avoid leaks
    delete args;

    return nullptr;
}

int main() {
    pthread_t thread1;

    // IMPORTANT: Allocate the struct on the heap, not the stack,
    // to ensure it still exists when the new thread accesses it.
    ThreadArgs* args = new ThreadArgs();
    args->id = 101;
    args->message = "Passing multiple values is easy!";

    // Create the thread, passing a pointer to the struct
    pthread_create(&thread1, nullptr, printArgs, (void*) args);
    pthread_join(thread1, nullptr);

    return 0;
}

    Sample Output:

    Thread ID: 101, Message: 'Passing multiple values is easy!'

    2. The Power of Parallelism

    Now, let's explore why using multiple threads can significantly speed up our programs. We'll do this by writing a program to count prime numbers in a given range, first sequentially and then in parallel.

    Measuring Time Accurately: Monotonic Clocks

    To measure the performance of our sequential and parallel code, we need an accurate timer. For benchmarking, we should use a monotonic clock. A monotonic clock is a clock that can only move forward and is not affected by system time changes (like a user manually changing the time or daylight saving adjustments). This property ensures that the time duration we measure between two points is always positive and accurately reflects the elapsed time. In C++, std::chrono::steady_clock is guaranteed to be monotonic and is the best choice for measuring time intervals.

    The isPrime() Function

    We need a function that does a fair amount of work to properly see the benefits of parallelism. Checking for prime numbers is a good example of a CPU-intensive task.

    // A simple function to check if a number is prime
bool isPrime(int n) {
    if (n <= 1) return false;
    for (int i = 2; i * i <= n; ++i) {
        if (n % i == 0) return false;
    }
    return true;
}

    Algorithm Explanation:

    This function checks if a number n is prime by trying to divide it by numbers starting from 2 up to the square root of n. If n is divisible by any number in this range, it cannot be a prime number. We only need to check up to the square root because if a number n has a divisor larger than its square root, it must also have a divisor smaller than it.

    The Full Program: Sequential vs. Parallel

    The program below will first count primes sequentially and then do it in parallel, finally printing a comparison of the results.

    #include <iostream>
#include <pthread.h>
#include <chrono>
#include <vector>

#define NUM_THREADS 4 // Feel free to change this based on your CPU cores

// isPrime function is defined above

// Struct to pass data to our prime counting threads
struct PrimeCounterData {
    int start;
    int end;
    int count;
};

void* countPrimes(void* arg) {
    PrimeCounterData* data = (PrimeCounterData*) arg;
    data->count = 0;
    for (int i = data->start; i < data->end; ++i) {
        if (isPrime(i)) {
            data->count++;
        }
    }
    return nullptr;
}

int main() {
    const int N = 200000;

    // --- SEQUENTIAL EXECUTION ---
    std::cout << "--- Sequential Execution ---" << std::endl;
    auto start_time_seq = std::chrono::steady_clock::now();
    int sequential_prime_count = 0;
    for (int i = 0; i < N; ++i) {
        if (isPrime(i)) sequential_prime_count++;
    }
    auto end_time_seq = std::chrono::steady_clock::now();
    std::chrono::duration<double> sequential_time = end_time_seq - start_time_seq;
    std::cout << "Primes found: " << sequential_prime_count << std::endl;
    std::cout << "Time taken: " << sequential_time.count() << " seconds" << std::endl << std::endl;

    // --- PARALLEL EXECUTION ---
    std::cout << "--- Parallel Execution (" << NUM_THREADS << " threads) ---" << std::endl;
    auto start_time_parallel = std::chrono::steady_clock::now();
    pthread_t threads[NUM_THREADS];
    PrimeCounterData thread_data[NUM_THREADS];
    int total_primes_parallel = 0;
    int chunk_size = N / NUM_THREADS;

    for (int i = 0; i < NUM_THREADS; ++i) {
        thread_data[i].start = i * chunk_size;
        thread_data[i].end = (i == NUM_THREADS - 1) ? N : (i + 1) * chunk_size;
        pthread_create(&threads[i], nullptr, countPrimes, &thread_data[i]);
    }

    for (int i = 0; i < NUM_THREADS; ++i) {
        pthread_join(threads[i], nullptr);
        total_primes_parallel += thread_data[i].count;
    }

    auto end_time_parallel = std::chrono::steady_clock::now();
    std::chrono::duration<double> parallel_time = end_time_parallel - start_time_parallel;
    std::cout << "Primes found: " << total_primes_parallel << std::endl;
    std::cout << "Time taken: " << parallel_time.count() << " seconds" << std::endl << std::endl;

    // --- ANALYSIS ---
    std::cout << "--- Analysis ---" << std::endl;
    double speedup = sequential_time.count() / parallel_time.count();
    double efficiency = speedup / NUM_THREADS;
    std::cout << "Speedup: " << speedup << std::endl;
    std::cout << "Efficiency: " << efficiency << std::endl;

    return 0;
}

    Sample Output (will vary based on your machine):

    --- Sequential Execution ---
Primes found: 17984
Time taken: 0.234567 seconds

--- Parallel Execution (4 threads) ---
Primes found: 17984
Time taken: 0.061234 seconds

--- Analysis ---
Speedup: 3.8309
Efficiency: 0.9577

    3. Thread Synchronization

    When multiple threads access and modify shared data concurrently, it can lead to unpredictable results. This situation is known as a race condition. The section of code accessing the shared resource is called the critical section.

    Demonstrating a Race Condition

    Let's look at a simple example where multiple threads increment a shared counter without any protection.

    #include <iostream>
#include <pthread.h>

#define NUM_THREADS 10
#define INCREMENTS_PER_THREAD 100000

long long shared_counter = 0;

void* incrementCounter(void* arg) {
    for (int i = 0; i < INCREMENTS_PER_THREAD; ++i) {
        shared_counter++; // RACE CONDITION HERE!
    }
    return nullptr;
}

int main() {
    pthread_t threads[NUM_THREADS];

    for (int i = 0; i < NUM_THREADS; ++i) {
        pthread_create(&threads[i], nullptr, incrementCounter, nullptr);
    }
    for (int i = 0; i < NUM_THREADS; ++i) {
        pthread_join(threads[i], nullptr);
    }

    std::cout << "Expected counter value: " << (long long)NUM_THREADS * INCREMENTS_PER_THREAD << std::endl;
    std::cout << "Actual counter value:   " << shared_counter << std::endl;

    return 0;
}

    Sample Output (will likely vary with each run):

    Expected counter value: 1000000
Actual counter value:   784321

    What Went Wrong? The shared_counter++ operation is not atomic; it's a sequence of read-modify-write. A race condition occurs when one thread reads the counter's value, but before it can write the new value back, the scheduler switches to another thread. That thread also reads the same original value. Both threads write back an incremented value, but one of the updates is lost.

    Fixing the Race Condition with Mutexes

    A mutex (mutual exclusion) is a synchronization primitive that acts like a lock. It can be used to protect a critical section, ensuring that only one thread can execute that code at a time.

    #include <iostream>
#include <pthread.h>

#define NUM_THREADS 10
#define INCREMENTS_PER_THREAD 100000

long long shared_counter = 0;
pthread_mutex_t mutex; // Declare the mutex

void* incrementCounter(void* arg) {
    for (int i = 0; i < INCREMENTS_PER_THREAD; ++i) {
        pthread_mutex_lock(&mutex);   // Lock the mutex
        shared_counter++;             // CRITICAL SECTION
        pthread_mutex_unlock(&mutex); // Unlock the mutex
    }
    return nullptr;
}

int main() {
    pthread_t threads[NUM_THREADS];

    pthread_mutex_init(&mutex, nullptr); // Initialize the mutex

    for (int i = 0; i < NUM_THREADS; ++i) {
        pthread_create(&threads[i], nullptr, incrementCounter, nullptr);
    }
    for (int i = 0; i < NUM_THREADS; ++i) {
        pthread_join(threads[i], nullptr);
    }

    pthread_mutex_destroy(&mutex); // Destroy the mutex

    std::cout << "Expected counter value: " << (long long)NUM_THREADS * INCREMENTS_PER_THREAD << std::endl;
    std::cout << "Actual counter value:   " << shared_counter << std::endl;
    return 0;
}

    Explanation: * pthread_mutex_init(&mutex, nullptr): Initializes the mutex before use. * pthread_mutex_lock(&mutex): A thread attempts to acquire the lock. If another thread holds it, this thread will wait (block). * pthread_mutex_unlock(&mutex): The thread releases the lock, allowing another waiting thread to proceed. * pthread_mutex_destroy(&mutex): Frees any resources associated with the mutex when it is no longer needed.

    Sample Output:

    Expected counter value: 1000000
Actual counter value:   1000000
